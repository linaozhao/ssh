## 旧实现与本轮变化

1. 旧 `controlled_cases.inspect_message` 将官方未知属性上的确定断言也计为 F。
   本轮要求与已知有效事实明确冲突才是核心 F；未知断言单列不确定原因。
2. 旧代码对解释整体判断 rejected/hypothetical；本轮以具体主张范围确定立场，
   被反驳的引文和后续本人正确陈述可以同时出现，不共享一个全局立场。
3. 旧评测先精确匹配候选、属性、全部规则 ID，再匹配引文和证据。
   本轮核心定位只比较消息、候选、属性、引文；规则/证据另评分。
4. 旧 `evidence_version` 兼容数字和证据 ID。本轮区分 `active_version`、
   `cited_version`、`conflicting_evidence_ids`、`cited_evidence_ids`。
   没有公开引用版本时不推断“实际脑中使用了旧版本”。
5. 错误决定无解释保留 unresolved；不强行 I。若决定有明确错误 F/R 前提，
   定位该前提，而非把同一因果链的决定重复标为 I 或 unresolved。
6. A/B1 已给目标消息的定位不是自主发现成绩；B2 不提供目标对象、消息或预设轮次。
7. M2 是新实现的两阶段流程。在线抽取器读取完整公共输入，程序只核验抽取结果；
   不调用样例构造解析器、不读取参考标签或分组变体。必要时最多再调用一次语义补充。
8. M1 是结构化有效状态辅助思路的新协议适配，不是旧提示词逐字复刻。
   提供各消息阶段有效事实、撤销证据及候选集合，不提供 F/R/I 或预设转移标签。

## 样例与独立核验范围

12 个旧基础题 family，沿用交替排序的 6/6 开发/留出划分。同族所有 A/B1/B2
任务同组。留出是新构造表达的评测，不是全新基础题泛化。

A/B2 使用原官方发布记录的明示前缀，停在有一个决定性违反项的观察点；
不改属性真假、不改规则、不借用未来证据。B1 使用原更新分支的事实更正。
开发/留出选用不同属性事实模板和规则/决定句式；A6 使用第三种等义表达。
部分自然表达仍共享词库，不能宣称模板完全独立。

程序核验包括：
- 官方记录重放；枚举未知属性可能取值，独立核验候选集合。
- 识别实际文本主张、立场和决定后计算标签；不以变体名直接赋标签。
- 引文范围、同步轮次可见性、同一智能体历史、组内材料与决定不变约束。
- B1 更正前后版本，B2 唯一最早错误与无错对照。

限制：程序参考与 M2 共用一部分形式关系核验代码，且有限语言识别器复用旧属性
词库。因此标为 program_verified，非独立人工金标。模型未表达的依据不得由构造元数据补全。

## 运行与预算

本地 CPU，GPU 不使用；不启动 MAD、不进行真实轨迹 Judge。
API 密钥仅通过隐藏输入注入进程，不保存或打印。接口模型目录已核验。
官方变更记录：https://api-docs.deepseek.com/updates/ ，2026-10-17 条目说明
`deepseek-flash` 路由至 DeepSeek-V4.1-Flash-1017。服务别名可能滚动更新，
无法获得不可变权重哈希；响应 model 字段逐次保留。

实际渲染输入的 UTF-8 字节数加封装余量用于保守 token 代理；不是官方精确分词。
在每次 M2 都触发补充且输出耗尽上限的极端情况下，预算代理约 4796 万 token；
实际硬上限为 4000 万，故极端情况下会明确停止，不无限调用。事前预算见 budget.json。
已完成的 6 个开发预检单元沿用相同指纹计入开发运行，未额外重采样。
