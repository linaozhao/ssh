# CBM 属性筛选任务与诊断定义

## 任务语义

每次输出表示“截至当前正式证据，尚未被排除的所有候选人”。对于固定的必要条件：

- 已知违反至少一个必要条件时排除候选人。
- 所有必要条件均已知满足时保留候选人。
- 部分条件未知但没有已知违反时仍保留候选人。

因此，未知不等于不满足，“尚未被排除”也不等于已经证明完全合格。该语义沿用 CBM-Attr v1，但 v2 使用不含具体候选集合示例的新协议；不同协议的模型结果不混算。

## 证据权限

- 题目中的正式证据决定当前事实。
- `correction` 只撤销 `supersedes_evidence_id` 指定的旧记录，并提供同一候选人、同一属性的新记录。
- `restatement` 不改变有效事实。
- 同伴发言是观点，不自动覆盖正式证据；同伴基于正式事实的有效推导可以帮助复核。
- 本轮只更新事实，不更新固定规则。
- 每个阶段的 oracle 只由当时已出现且仍有效的证据计算，禁止读取未来事实。

## 可观察诊断范围

诊断对象是公开答案集合与公开解释。输出文字可以证明“模型写出了什么”，不能证明模型内部遗忘、压力、从众或其他认知机制。

四个维度分别记录：

1. **结果**：正确、有效错误、不可识别。
2. **过程**：初始错误、新引入、持续、纠正、复发、合理更新、正确保持、不确定。
3. **内容**：`factual_deviation`、`rule_deviation`、`inference_application_error`、`unresolved`，允许多标签。
4. **文本关联**：当前文本引用或重复了哪些当时可见的同伴消息。

“首次观察到偏离”与“此前正确、随后明确变错”是不同字段。采用同伴答案只是关联信号，不自动构成因果解释。

## 三种证据条件

- `clean_stay`：T1-T3 逐步提供目标证据，T4-T5 只重述，不改变 oracle。
- `evidence_update`：T1-T3 与 clean 完全相同；T4 明确更正旧证据且 oracle 必须改变；T5 不再改变 oracle。
- `irrelevant_noise`：目标证据和 oracle 与 clean 每阶段完全相同；只在 T4-T5 加入领域相关非目标事实。

这些条件不是预设类别。每个条件都检查所有适用内容与过程类别。

## 方法来源与边界

本项目借鉴 [CBM](https://arxiv.org/abs/2605.30219) 的“保持、更新、隔离”问题，用有限候选空间和符号验证器获得逐阶段标准状态；它不是 BeliefTrack 的 Rule Discovery 或 Circuit Diagnosis 复现。MAD 的公开轨迹定位参考 [Stay Focused](https://aclanthology.org/2026.findings-eacl.268/)，故意避免把答案变化直接等同于 problem drift。多智能体失败模式的证据组织参考 [MAST](https://arxiv.org/abs/2503.13657)，但本轮只提出属性筛选任务中的开发性预标注类别。
